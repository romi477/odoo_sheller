# Odoo 18

Python 3.10 or newer.

## Python

- Cache: `env.flush_all()`, `records.flush_model()`,
  `records.flush_recordset()`, `env.invalidate_all()`,
  `records.invalidate_model()`, `records.invalidate_recordset()`. In the
  shell {{commit}} and {{rollback}} already do this; you need it only inside a
  script that writes and then reads back with SQL.
- `name_get` is gone. The label is `display_name`, computed by
  `_compute_display_name`; search on it goes through
  `_search_display_name`, and `_rec_names_search` lists the fields it
  searches.
- Access is one call each: `records.check_access('write')` raises,
  `records.has_access('write')` answers, `records._filtered_access('read')`
  narrows. They cover rights and record rules together.
  `check_access_rights` and `check_access_rule` still run, warn as
  deprecated since 18.0, and delegate. Write the new names.
- Field aggregation is `aggregator='sum'`. `group_operator` still loads and
  warns: `Since Odoo 18, 'group_operator' is deprecated, use 'aggregator'
  instead`.
- `_read_group(domain, groupby, aggregates)` is the grouping call for code
  and returns tuples, aggregates spelled `'amount:sum'` or `'__count'`.
  `read_group(domain, fields, groupby)` still exists for the web client.
- SQL constraints are still `_sql_constraints = [(name, sql, message)]`.
  `models.Constraint` is 19.
- `SQL` (`from odoo.tools import SQL`) is the way to compose a raw query
  with its parameters. A string with a params tuple still runs. Never build
  the query with `%` or an f-string on a plain string.
- Translations: `self.env._("Text %s", value)` in model code.
- A model with companies can declare consistency instead of checking it by
  hand: `_check_company_auto = True` on the model and `check_company=True`
  on each `Many2one` that must match `company_id`.
- `res.users.groups_id` and `res.groups.users` are still the membership
  fields; a group's category is still `category_id`.
- `ir.config_parameter`: `get_param(key, default)` and `set_param`.

## XML

- The list view root is `<list>`, the view type is `list`, `view_mode` is
  `list,form`, and an xpath into a list says `//list`. `<tree>` is not a
  view type any more and no alias rewrites it; a `view_mode` that says
  `tree` does not open the list.

  ```xml
  <list string="Things">
      <field name="name"/>
  </list>
  <xpath expr="//list/field[@name='name']" position="after"/>
  ```

- Modifiers are Python expressions on the attribute, as in 17:
  `invisible="state == 'cancel'"`, `column_invisible="True"`. `attrs` and
  `states` stay gone.
- A kanban card is `<t t-name="card">`. `kanban-box` still loads, and the
  client warns `'kanban-box' is deprecated, define a 'card' template
  instead`. Write `card`.
- QWeb output is `t-out`. `t-raw` is deprecated and warns.
- Access is `security/ir.model.access.csv`, record rules are `ir.rule`.
- A JSON controller is `@http.route(..., type='json')`. `jsonrpc` is 19.
